# 작업 현황과 남은 작업


## 0. 보는 법

- **선행** 칸의 작업이 끝나야(또는 결정이 나야) 시작할 수 있음, 선행에 적힌 이름은 이 문서의 다른 항목임

| 분야 | 하는 일 |
| --- | --- |
| 결정 | 프로젝트 담당자가 정해야 하는 규칙·수치. 정해지기 전에는 관련 구현 시작 안 함 |
| 의학 | 의학 정보 검토. 출처는 대한당뇨병학회 진료지침, ISPAD, ADA 세 가지로 한정함 |
| 기획 | 게임 내용, 화면 흐름, 문구 |
| 코드 | C# 스크립트와 EditMode 테스트 |
| 씬 | Unity 에디터에서 씬·UI 배치 |
| 그래픽 | 3D 모델, 애니메이션, 2D 그림, UI 디자인, 효과 |
| 사운드 | 배경음, 효과음, 음성 |
| 빌드 | Android 빌드, 실기기 확인, 배포 준비 |

- 공개 리포지토리이므로 유료 에셋, 라이선스가 불분명한 그림·소리·글꼴은 커밋 안 함. 외부 에셋을 쓰면 라이선스를 PR에 적음

## 1. 방향

- 대상을 1형에서 1형·2형 당뇨 아동으로 넓힘. 시작할 때 유형을 고르고 유형별 대처법으로 다른 게임을 함
- 러너 코어, 무한 주행, 구간 틀, 맵, 음식 아이템, 결과 화면은 두 유형이 같이 씀
- 2형 대처는 choose(음료·음식 고르기) → move(달리기·쉬기) → notice(신호 알아채기) → tell(어른에게 알리기) 4단계
- 식사, 운동, 수면, 도움 요청, 혈당 관리 습관은 유형 상관없는 공통 학습으로 주행 안에 녹임
- 1구간은 신호 인식과 기본 익히기. 튜토리얼은 유형을 고른 뒤 첫 판에 따로 함([tutorial.md](tutorial.md)). 2·3구간은 학교 운동장, 놀이터, 가족 나들이 같은 생활 환경 맵에서 진행
- 퀴즈 관문보다 구간별 주행을 먼저 함
- 성공 기준: 판이 끝난 뒤 아이가 "재밌다", "혈당 관리가 중요하다"를 함께 느낌
- 자세한 내용과 남은 결정은 [type-tracks.md](type-tracks.md)에 있음

## 2. 역할 분담

- 구조 담당 팀원 1명, 영역 담당 팀원 3명: 팀원1(캐릭터), 팀원2(월드), 팀원3(화면)
- 구조 담당 팀원이 `dev`에서 작업 브랜치를 만들어 큰 틀(규칙 코드, 빈 틀 스크립트)을 push하면, 영역 담당 팀원은 그 브랜치를 받아 그 위에서 빈 틀을 채우고 push함. 채우는 규칙은 [team-rules.md](team-rules.md) 2.1절, 브랜치 흐름은 8절에 있음
- 작업 브랜치를 `dev`에 머지하는 것은 구조 담당 팀원이 함
- 영역 담당 팀원은 자기 영역의 그림·모델, 소리, 기획 초안, 프리팹, 빈 틀 채우기를 함께 맡음

| 데이터 내보내기(Exporter) | 결정, 코드 | 인터넷 권한 없이 기기 안에서 내보내는 방식이어야 함 |
