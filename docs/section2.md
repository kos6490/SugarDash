# 2구간(조건별 판단)과 하루 흐름

- 범위: 2-A 공통 틀(구현함). 2-B 유형별 조건 이벤트는 후보만 적는다(7절).
- 수치: 새 수치는 모두 PLACEHOLDER(`null`)다. 에디터 개발 설정(`Config/Dev/`)에만 테스트 픽스처 값을 쓴다.
- 의학 정보: 운동·수면·외식·놀이가 혈당에 주는 영향은 방향(오르는지 내리는지)까지 포함해 세 출처(대한당뇨병학회 진료지침, ISPAD, ADA)로 확인한 뒤 정한다. 2-A는 값이 들어갈 자리만 만든다.
- 바탕: [type-tracks.md](type-tracks.md) 8절, [type-select.md](type-select.md), [log-format.md](log-format.md), [dev-scene.md](dev-scene.md) 6.9·6.10·9.12절

## 1. 목적

1구간(신호 인식)을 지나면 2구간(조건별 판단)이 이어진다. 2구간에서는 아이가 생활하는 곳을 하루 흐름에 따라 달린다. 같은 상황이라도 지금 어느 맵에 있는지에 따라 나은 행동이 달라지는 것을 겪게 하는 것이 "조건별 판단"이다.

- 맵 하나가 하루의 한 때이고, 하루가 끝없이 되풀이된다.
- 맵이 바뀌면 그래픽(맵, 낮·밤 조명)과 규칙(맵별 설정 덮어쓰기)이 함께 바뀐다.
- 밤에는 짧은 집 장면과 수면 전환(암전)이 있다.
- 두 유형이 같은 틀을 쓰고, 맵별 조건 값은 유형별 설정 파일에 둔다.

하지 않는 것:
- 수면 장면을 메뉴나 멈춤 패널로 만들지 않는다. 세계를 멈추는 것은 어른이 필요한 위급한 순간뿐이다.
- 맵이나 시간대 때문에 음식을 "나쁜" 것으로 보이게 하지 않는다(외식 맵에서 음식을 먹었다고 바로 지치는 연출 등).
- 출처 확인 전에 "운동하면 혈당이 내려간다" 같은 방향을 값으로 정하지 않는다.

## 2. 하루 흐름

```
1구간 signal ──(signal.lengthM)──→ 2구간 condition
                                   아침·운동장 → 오후·놀이터 → 저녁·나들이 → 밤·집 → (다음 날) 아침·운동장 → …
```

| 순서 | 장면 id | 때 | 성격 |
| --- | --- | --- | --- |
| 1 | `schoolyard` | 아침 | 학교 운동장 |
| 2 | `playground` | 오후 | 놀이터 |
| 3 | `outing` | 저녁 | 가족 나들이 |
| 4 | `home` | 밤 | 짧은 장면. 트랙 물체가 나오지 않고, 끝나면 수면 전환 뒤 다음 날 아침 |

- 장면마다 길이(m)가 있고 누적 거리로 바뀐다. 마지막 장면이 끝나면 첫 장면으로 돌아가고 하루 번호(`dayIndex`, 첫날 0)가 하나 오른다.
- 1구간에는 장면이 없다. 속도는 판 전체에서 계속 빨라지고 하루가 넘어가도 처음으로 돌아가지 않는다.
- 집 장면에서는 장애물·음식·간식·쉬는 곳이 나오지 않는다. 집에 들어가는 순간 앞에 놓여 있던 것도 치운다.
- 다음 날 첫 장면에 들어가면 화면이 짧게 어두워졌다 밝아진다. 연출만이고 세계와 혈당 시간은 멈추지 않는다. 물체는 계속 멀리 앞에만 놓이므로 어두운 동안 바로 앞에 피할 물체가 갑자기 생기지 않는다.
- 집 장면에서도 혈당은 흐르므로 저혈당·고혈당 대처가 나올 수 있고, 지금 규칙대로 진행한다. 대처 중 세계가 멈춘 동안에는 장면이 바뀌지 않는다.

## 3. 설정

두 유형 설정 파일 모두 `sections`가 이 모양이다(빌드 설정은 길이가 모두 `null`).

```json
"sections": [
  { "id": "signal", "lengthM": null },
  {
    "id": "condition",
    "scenes": [
      { "id": "schoolyard", "timeOfDay": "morning",   "lengthM": null, "overrides": {} },
      { "id": "playground", "timeOfDay": "afternoon", "lengthM": null, "overrides": {} },
      { "id": "outing",     "timeOfDay": "evening",   "lengthM": null, "overrides": {} },
      { "id": "home",       "timeOfDay": "night",     "lengthM": null, "spawns": false }
    ]
  }
]
```

- 개발 설정: `signal` 300m, 운동장·놀이터·나들이 200m씩, 집 140m. 1형 개발 설정의 나들이만 간식 간격을 3~4초로 덮어써 맵이 바뀌는 것을 눈으로 볼 수 있다.
- `spawns`를 생략하면 `true`다.

### 3.1 덮어쓰기(`overrides`)

장면에 있는 동안 전역 값 대신 쓰는 값이다. 적지 않은 키는 전역 값을 그대로 쓴다. 빌드 설정에서는 2-B에서 출처를 확인할 때까지 비워 둔다.

| 키 | 유형 | 바꾸는 전역 값 |
| --- | --- | --- |
| `runDecayPerSec` | 두 유형 | `glucose.runDecayPerSec` |
| `suddenDropChancePerSec` | 1형 | `suddenDrop.chancePerSec` |
| `trackSnackIds` | 1형 | 트랙에 나오는 간식 목록(지금은 `snacks` 전부). 같은 id를 여러 번 적으면 더 자주 나온다 |
| `trackSnackIntervalMinSec`, `trackSnackIntervalMaxSec` | 1형 | `runner.` 같은 이름 |
| `foodRowIntervalMinSec`, `foodRowIntervalMaxSec` | 2형 | `runner.` 같은 이름 |
| `restIntervalMinSec`, `restIntervalMaxSec` | 2형 | `runner.` 같은 이름 |

- 불러올 때 검증한다: 덮어쓴 값은 전역 값과 같은 규칙, 간격은 덮어쓴 뒤의 min·max 쌍으로 검사, `trackSnackIds`는 `snacks`에 있는 id만. 그 유형에 없는 키나 표에 없는 키는 로드 실패다(오타가 조용히 무시되지 않게).

## 4. 기록

- 장면에 들어갈 때마다 `SceneEntered` 레코드가 남는다. 필드: `scene`, `timeOfDay`, `dayIndex`, `distanceM`, `simT`, `t`([log-format.md](log-format.md)).
- 다른 레코드에 장면 필드를 붙이지 않는다. 어느 장면에서 일어난 일인지는 시각으로 다시 계산한다.
- 점수 규칙은 바뀌지 않는다.

## 5. 영역 빈 틀

| 영역 | 빈 틀 | 받는 것 | 채울 것 |
| --- | --- | --- | --- |
| 월드 | `World/SceneLook` | `SceneEntered`(장면 id, 때) | 장면별 맵 배경(운동장, 놀이터, 나들이, 집), 때별 조명·하늘. 지금은 바닥 색만 바뀐다 |
| 월드 | `World/TrackItemLook` | 지금 장면 id(`SceneId`) | 장면별 장애물 모양(운동장 축구공, 놀이터 미끄럼틀 등). 1구간 일과 같은 파일이다 |
| 화면 | `Screen/SleepTransitionView` | 하루가 넘어감(`SceneEntered`의 `dayIndex`가 오름) | 잠자는 그림이나 해·달 전환. 바로 검게 한 뒤 밝힌다(서서히 어두워지면 바뀐 맵이 먼저 보임). 길이는 Inspector 값(`Hold Sec`, `Fade In Sec`) |

- 빈 틀은 받은 것을 보여 주기만 한다. 세계·혈당을 멈추거나 바꾸지 않는다.
- 씬 연결은 [dev-scene.md](dev-scene.md) 6.9·6.10절, 확인 방법은 9.12절이다.

## 7. 2-B 후보 (정하지 않음)

모두 출처 확인 뒤 별도 설계에서 정한다. 담당 팀원이 개발하면서 세 출처에서 찾아 근거를 붙여 제안하고, 판본·쪽수는 담당자가 확인한다.

| 맵 | 1형 | 2형 |
| --- | --- | --- |
| 운동장·아침 | 운동 구간(체육 시간)에서 혈당 하강 값. 운동 전 혈당 재기 습관 순간 | 운동 구간에서 계속 달릴지 쉴지 |
| 놀이터·오후 | 많이 뛰어노는 곳이라 급하강 확률 값 | 쉬는 곳이 많아 쉬기와 움직이기 사이 균형(쉬는 곳 간격 값) |
| 나들이·저녁 | 트랙 간식 구성·간격 | 음식 줄 간격이 짧아짐(몰아서 먹는 상황) |
| 집·밤 | 수면의 혈당 영향, 잠자리 레인 고르기 | 같음 |

- 2형 혈당 재기 습관: 2형에는 측정기가 없으므로 넣지 않았다. 담당 팀원이 출처를 찾아 정한다.
- 1형 나들이의 외식 음식(햄버거 등)은 "1형 주행에서 일반 음식 처리"가 정해지지 않아 내지 않는다.
- 1형 나들이 조건이 약하다: 1구간에도 빠른 당과 느린 당 간식이 섞여 나오므로, 2-A에서 바꿀 수 있는 것은 구성 비율과 간격뿐이다.
- 운동 구간을 맵 전체가 아니라 맵 안 일부(체육 시간)로 둘지는 2-B에서 정한다. 지금 덮어쓰기는 장면 단위다.
- 1형 "빈 간식 가방"(2단계에서 빠른 당이 없을 때 알리기를 정답으로 두는 안)은 판정 규칙을 바꾸고 의학 확인이 필요해 3구간 후보다.

## 8. 팀원별로 알아야 할 것

### 공통
- 빈 틀은 받은 것을 보여 주기만 한다. 세계·혈당을 멈추거나 바꾸지 않는다.
- 하루 흐름 확인 방법은 6절과 [dev-scene.md](dev-scene.md) 9.12절이다.
- 화면·오브젝트의 모양(크기, 위치, 색, 그림, 애니메이션, 소리, 문구)은 바꿔도 되고 구조는 바꾸지 않는다([team-rules.md](team-rules.md) 2.3절).

### 팀원1(캐릭터)
- 2구간에서 새로 할 일은 없다.

### 팀원2(월드)
- `World/SceneLook`: 장면 4개(운동장 아침, 놀이터 오후, 나들이 저녁, 집 밤)의 맵 배경과 때별 조명·하늘.
- `World/TrackItemLook`: 장면별 장애물 모양(운동장 축구공, 놀이터 미끄럼틀 등). 1구간과 같은 파일이다. 모양이 바뀌어도 장애물 종류 3개는 그대로 둔다.
- 맵이나 시간대 때문에 음식이 "나쁜" 것으로 보이게 하지 않는다.

### 팀원3(화면)
- `Screen/SleepTransitionView`: 하루가 넘어갈 때 잠자는 그림이나 해·달 전환. 서서히 어두워지게 하지 말고 바로 검게 한 뒤 밝힌다. 이 순서는 구조라서 바꾸지 않는다(서서히 어두워지면 바뀐 맵이 먼저 보인다). 그림과 밝아지는 모습은 바꿔도 된다([team-rules.md](team-rules.md) 2.3절). 길이는 Inspector 값(`Hold Sec`, `Fade In Sec`)이다.
