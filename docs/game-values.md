# 게임 표현값

출처로 정하지 않고 게임의 재미와 난이도로 정하는 값이다. 실제 수치가 아니며 아동 플레이 테스트에서 조정한다. 출처로 정한 혈당 기준값은 [glucose-evidence.md](glucose-evidence.md), 음식 등급은 [food-evidence.md](food-evidence.md)에 있다.

- 정한 값은 빌드 설정(`Assets/_Project/Config/game-config.json`, `game-config.type2.json`)에 넣는다. 에디터 개발 설정(`Config/Dev/`)은 그대로 둔다.
- 출발점은 개발 설정 값이다. 저학년용으로 제한 시간은 넉넉하게 시작한다.
- 묶음을 모두 정하면 빌드 설정이 불러와져 설정 검증 테스트(불변식)가 돌기 시작한다. 그때 어긋나는 값을 함께 고친다.

## 1. 시간 (2026-11-09)

| 설정 | 1형 | 2형 | 뜻 |
| --- | --- | --- | --- |
| `time.timeScale` | 150 | 150 | 실제 1분을 게임 0.4초로 줄인다. 다시 재는 15분은 게임 6초 |
| `display.delaySec` | 3 | 없음 | 혈당바가 실제 혈당을 늦게 따라오는 시간 |
| `hypo.step1TimeLimitSec` | 10 | 없음 | 측정기 누르기 |
| `hypo.step2~4TimeLimitSec` | 10 | 없음 | 빠른 당·양·재확인 고르기 |
| `type2.tellTimeLimitSec` | 없음 | 10 | 2형 tell 고르기 |
| `hyper.notifyTimeLimitSec` | 10 | 없음 | 1형 고혈당 알리기 |
| `guardianPromptTimeLimitSec` | 8 | 8 | 오류 뒤 "어른에게 알리기" |
| `resumeCountdownSec` | 3 | 3 | 다시 달리기 전 3-2-1 |
| `graceSec` | 3 | 3 | 다시 달린 뒤 장애물·발동 없는 시간 |
| `answerFeedbackSec` | 1.5 | 1.5 | 고른 결과 문구를 읽을 시간 |
| `type1.habitCheckWindowSec` | 5 | 없음 | 혈당 재기 습관 말풍선 |
| `time.fastForwardTickSimSec` | 0.5 | 없음 | 재확인 빨리감기 단위(보이지 않는 값) |

- 2형 값은 1형의 같은 뜻 값과 맞췄다.
- 불변식 "1단계 제한 시간 > 표시 지연"(10 > 3)은 지켜진다.

## 2. 혈당 흐름 (2026-11-09)

| 설정 | 1형 | 2형 | 뜻 |
| --- | --- | --- | --- |
| `glucose.initial` | 120 | 120 | 시작 혈당. 적정 범위(70~180) 안 |
| `glucose.min` / `max` | 20 / 400 | 20 / 400 | 혈당이 갈 수 있는 끝 |
| `glucose.baseDecayPerSec` | 0.5 | 0.3 | 시간이 지나며 내려가는 속도(게임 초당 mg/dL) |
| `glucose.runDecayPerSec` | 1 | 0.7 | 달리는 동안 더 내려가는 속도. 1형은 합쳐 1.5/초로 120에서 약 33초 뒤 70 |
| `glucose.hypoReleaseMargin` | 10 | 10 | 80 위로 올라와야 저혈당이 다시 날 수 있다 |
| `glucose.hyperReleaseMargin` | 20 | 20 | 230 아래로 내려와야 고혈당 알리기가 다시 뜰 수 있다 |
| `recurrence.cooldownSec` | 10 | 없음 | 대처 뒤 저혈당이 다시 나기까지 최소 시간 |
| `display.warningThreshold` | 80 | 없음 | 표시 혈당이 이 아래면 게이지 경고 |
| `symptom.shakeStartGlucose` | 80 | 없음 | 실제 혈당이 이 아래면 화면이 흔들리기 시작 |
| `elimination.glucoseHigh` | 300 | 300 | 고혈당 알리기(250)를 놓친 뒤 탈락까지 여유 50. 출처에 250보다 높은 단계가 없어 게임 표현값이다 |

- 2형 하강은 개발 설정 값을 그대로 썼다. 2형도 달리면 내려가는 규칙을 둘지는 아직 정하지 않았다(roadmap 4.3).

## 3. 처치량과 등급별 상승량 (2026-11-09)

등급마다 같은 값을 쓰고 두 유형도 같은 값을 쓴다. 등급과 근거는 [food-evidence.md](food-evidence.md). 1형 간식 설정은 게임 초, 2형 음식 설정은 실제 분이라 시간 압축 150으로 맞췄다(실제 1분 = 게임 0.4초).

| 등급 | 1회분 상승 | 오르기 시작 | 흡수 시간 | 1형 간식 | 2형 음식 |
| --- | --- | --- | --- | --- | --- |
| 빠르게 올림 | 31.5 | 2.5분(게임 1초) | 5분(게임 2초) | 주스, 탄산음료 | 주스, 탄산음료 |
| 천천히 올림 | 15 | 5분(게임 2초) | 12.5분(게임 5초) | 크래커, 사과 | 사과, 크래커 |
| 늦게 오래 올림 | 25 | 10분(게임 4초) | 25분(게임 10초) | 없음 | 치킨, 피자, 햄버거 |
| 당 없음 | 0 | 1분 | 1분 | 없음 | 물 |

- 처치량 배수(`hypo.doses`, 1형): 조금 1, 알맞게 2, 많이 3. 주스 기준 31.5 / 63 / 94.5로 근거 범위 54~72([glucose-evidence.md](glucose-evidence.md) A-4)보다 적음 / 가운데 / 많음이다.
- 트랙 간식(`runner`, 1형): 1회 0.5회분, 6~10초 간격.
- 늦게 오래 올림은 "처음에는 덜, 뒤에 오래"를 오르기 시작과 흡수 시간으로 나타낸 것이다. 1회분 상승은 대략 값이다.
- 1형 2단계 선택지는 사건마다 빠른 당 하나와 느린 당 하나를 무작위로 골라 보여 준다(`ChoiceOrder.RespondSnacks`). 간식이 4개라 모두 띄우면 버튼이 7개가 되기 때문이다.

## 4. 이벤트와 맵 (2026-11-09)

모두 개발 설정 값 그대로다.

| 설정 | 1형 | 2형 | 뜻 |
| --- | --- | --- | --- |
| `suddenDrop` | 0.01/초, 20, 5초 | 없음 | 1초마다 1% 확률로 5초 동안 20 떨어진다 |
| `type2.highHoldSec` / `lowHoldSec` / `noticeSec` | 없음 | 4 / 4 / 2 | 높거나 낮은 상태가 4초 이어지면 신호, 신호 2초 뒤 tell |
| `runner.foodRowInterval*` | 없음 | 4~7초 | 음식 줄 간격 |
| `runner.restInterval*`, `restDurationSec` | 없음 | 15~25초, 3초 | 쉬는 곳 간격, 쉬는 시간 |
| 구간 길이 `lengthM` | 1구간 300m, 2구간 장면 200m(집 140m) | 같음 | 한 판 안에서 구간·장면이 바뀌는 거리 |
| 운동장 `runDecayPerSec` | 1.3 | 없음 | 운동장에서 달리기 하강이 커진다 |
| 놀이터 `restInterval*` | 없음 | 8~12초 | 쉬는 곳이 더 자주 나온다 |
| 나들이 `foodRowInterval*`, `foodRowIds` | 없음 | 2.5~4초, 물·주스·탄산음료·치킨·피자·햄버거 | 음식 줄이 더 자주, 외식 음식 위주로 나온다 |
